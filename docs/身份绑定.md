# 身份绑定说明（业主 / 员工 / 客户）

## 客户
- **不**走登录页。打开业主/员工发出的商品分享落地页 `pages/share/landing/landing?shareId=`。
- 后台静默 `wx.login` → `/api/auth/login`（`preferRole=customer`）→ openid。
- openid **未**在 `tenant_members` → 角色 `customer`，`customer_profiles` 自动建档（访客即客户）。
- **限制分享**：占 `share_event_bindings` 名额（前 N 位）；**公开分享**：不占名额。

## 业主（管理员）
1. **首位业主**：档口尚无真实业主时，在小程序首页点「微信登录（员工身份）」且 `preferRole=owner`，真实微信登录成功后自动写入 `tenant_members.role=owner`。
2. **之后的业主**：由现有业主在「设置 → 员工邀请」生成邀请（角色选「业主」）→ 对方扫小程序码 / 输入邀请码，登录时带 `inviteCode`，`InvitesService.acceptByCode` → `ensureMember(..., 'owner')`。

## 员工（营业员）
- 仅能通过业主邀请：设置页生成邀请（角色「营业员」）→ 扫码/邀请码登录绑定 `tenant_members.role=staff`。
- 开发态 `DEV_FAKE_LOGIN=true` 可用假 code + `preferRole=staff|owner` 直接建成员（仅本地）。

## 判定顺序（登录）
1. openid 已是成员 → 用成员角色  
2. 假登录 + preferRole → 建成员（开发）  
3. 真实微信 + preferRole=owner 且档口无真实业主 → 首位业主  
4. 带 inviteCode → 接受邀请成为 owner/staff  
5. 否则 → 客户建档
