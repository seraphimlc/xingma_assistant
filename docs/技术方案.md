# 羊毛衫档口商品与客户管理小程序 — 技术方案

> 形态：每位业主一个独立微信小程序；统一 SaaS 多租户后端；AppID → tenantId 映射，数据严格隔离。  
> 技术栈：原生微信小程序 + NestJS + MySQL + Redis + 对象存储（OSS/COS 适配）。

## 3. 核心鉴权与权限判定

### 3.1 登录（code2session → JWT）

**客户无登录 UI**：客户不主动登录；分享落地页（`share/landing`）后台静默 `wx.login` → 调同一 `POST /api/auth/login` 换 openid/JWT 后立刻跳转商品详情。首页对客户只提示「请通过分享卡片打开」，不展示「微信一键登录」。业主/员工在首页显式登录进入管理端。

```
小程序 wx.login() → code（客户：分享落地静默；员工：首页点击）
    → POST /api/auth/login { code }
    → 后端用租户 AppSecret 调微信 jscode2session
    → 得到 openid（+ session_key 仅存服务端/Redis）
    → 查 tenant_members / customer_profiles
    → 签发 JWT: { tenantId, openid, role, memberId?, customerId? }
    → 小程序后续请求 Authorization: Bearer <token>
```

伪代码：

```ts
async function login(appId, code) {
  const tenant = tenants.resolveByAppId(appId); // 未注册则拒绝
  const { openid } = await wechat.code2Session(tenant.wxAppId, tenant.wxAppSecret, code);
  const member = await members.find(tenant.id, openid);
  if (member) return signJwt({ role: member.role, memberId: member.id, ... });
  const customer = await customers.find(tenant.id, openid); // 可能尚不存在
  return signJwt({
    role: 'customer',
    customerId: customer?.id, // 首访分享时再 ensureProfile
    tenantId: tenant.id,
    openid,
  });
}
```

### 3.2 商品访问判定公式

```
canView(user, product, ctx):
  if user.role in {owner, staff}: return ALLOW

  rule = findCustomerProductRule(user.customerId, product.id)
  if rule.effect == deny:  return DENY
  if rule.effect == allow: return ALLOW

  policy = product.sharePolicy ?? productLevel.defaultSharePolicy

  switch policy:
    case open:
      return ALLOW
    case level_match:
      return customer.rank >= productLevel.minCustomerRank ? ALLOW : DENY
    case designated_only:
      // 必须经分享入口，且当前客户 == ShareEvent.boundCustomerId
      if !ctx.shareEventId: return DENY(need_share_entry)
      if !share.boundCustomerId: return DENY(awaiting_bind) // 由 openShare 先绑定
      return user.customerId == share.boundCustomerId ? ALLOW : DENY
```

### 3.3 「仅指定客户」绑定时机（不预先选客户）

```
员工创建分享:
  ShareEvent { productId, sharePolicy: designated_only, boundCustomerId: null }
  → 生成 path: /pages/share/landing/landing?shareId=xxx
  → 员工可转发给微信好友（不必在系统里点选客户）

客户 A 第一次打开该分享（全程无登录页）:
  1. 落地页后台静默 wx.login → JWT（openid）
  2. GET /api/shares/:shareId/open
  3. ensureProfile(openid) → 自动建档 + 默认客户等级
  4. 若 boundCustomerId 为空 → 写入 boundCustomerId = A.id, boundAt = now
  5. redirect 商品详情（含签名图片 URL）

客户 B（或其他人）再次打开同一 shareId:
  1. 静默鉴权得到 B
  2. openShare 发现已绑定 A
  3. B.id !== A.id → 403 拒绝商品内容与图片

允许客户继续分享:
  仍按「商品等级 + 客户等级 + 例外规则」判定 canReshare；
  客户二次分享会生成新的 ShareEvent（新 shareId），绑定逻辑同上。
```

时序简图：

```
员工                小程序               API                DB
 |--创建分享()------->|-- POST /shares --->|-- insert ShareEvent(bound=null)
 |<-- path --------|<-- shareId --------|
 |-- 转发给客户A
        客户A -->| landing?shareId
                 |-- login ------------>|-- code2session
                 |-- GET .../open ----->|-- ensure customer
                                        |-- bind if null
                                        |-- assert visitor==bound
                                        |-- return product + signed URLs
```

## 6. 图片上传与签名访问流程

```
【上传】
员工选图 → POST /api/media/upload-credential
         → 返回 { objectKey: tenants/{tenantId}/..., uploadUrl, headers, expireAt }
         → 客户端直传 OSS/COS（STS / PostObject）
         → 后端登记 MediaAsset（仅存 objectKey，不存永久公网 URL）

【访问】
列表/详情/分享 open 接口先做 canView
  → 通过后返回 mediaIds（或由单独 sign 接口换 URL）
  → POST /api/media/sign { objectKey }
  → 校验 objectKey 属于当前 tenantId
  → 返回短时签名 URL（如 10 分钟 TTL）
  → 小程序用临时 URL 展示 <image>
```

原则：URL 泄露也不应长期可读；分享拒绝时不得签发该商品图片。

## 10. 决策摘要（已落地到骨架）

1. **多租户**：统一后端 + AppID 映射，表级 `tenant_id` 隔离。  
2. **定向分享**：创建时不选客户；客户无登录 UI，首访静默 openid 建档并绑定 `ShareEvent`；其后身份比对。  
3. **图片**：租户目录 + 短时签名，接口层鉴权。  
4. **价格**：`price_display=hide` 时统一文案「价格请询价」。  
5. **等级**：客户等级仅人工调整；商品等级驱动默认分享策略。  
6. **询价**：纯文字，关联单商品。
